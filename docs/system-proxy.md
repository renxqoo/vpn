# 系统代理启停

状态：已核销（2026-10-19）。级别：中。沿用 feature-dev-v2 的方案、测试计划与独立审查流程。

## 契约与裁决

用户要求 start 自动设置系统代理端口并启用，以及支持关闭。按当前 macOS 环境实现系统代理接管；其它平台仍可使用代理内核及 --no-system-proxy 手动配置。

- macOS `start`：本地 HTTP/SOCKS/API 全部监听成功后，保存各启用网络服务的 HTTP/HTTPS/SOCKS 地址及开关、PAC 开关/URL、自动发现开关，再设置 127.0.0.1:实际 HTTP/SOCKS 端口并启用。HTTPS 使用 HTTP CONNECT 端口。原 PAC 和自动发现暂时关闭，绕过列表不改。
- `start --no-system-proxy`：仅启动内核。Linux/Windows start 输出不支持自动接管的提示，保持原内核行为。
- `stop [--api-port PORT]`：通过鉴权 API 恢复本程序接管的系统代理，然后停止内核；未运行时也可恢复崩溃遗留快照。幂等，不通过裸 PID 杀进程。
- `proxy off`：仅恢复系统代理，保留内核；恢复原代理可能重新启用启动前已有的代理。
- SIGINT/SIGTERM/SIGHUP：先恢复系统代理，再停内核。恢复失败时保留快照与内核，明确报错，可修复权限后重试。SIGKILL/断电无法执行恢复，可用 proxy off/stop 或下次 start 恢复快照。
- 原代理带认证时在修改前拒绝接管（networksetup 无法读回密码以可靠恢复），可使用 --no-system-proxy。
- 地址设置失败先回滚；回滚成功则启动失败并关闭监听器；回滚仍失败则保留可用内核与控制端点，避免系统代理指向不存在的服务，明确报错进入可恢复状态。
- 恢复仅处理仍由本程序接管的代理项，用户/其它软件改过的地址保留。已删除的网络服务跳过。恢复部分失败保留快照供重试，不误报成功。
- macOS/Linux 控制端点与代理快照记录进程启动时间，识别崩溃后 PID 被复用的陈旧记录；无法读取进程身份时保守保留存活判断。
- 新增 POST /system-proxy/off（204 成功、400 恢复失败、501 无回调）与 POST /shutdown（先恢复，204 响应发出后异步停止）。复用现有 Host/secret 防护，关闭期间重复请求幂等，拒绝新重载。

## 一致性与预算

快照 ~/.vpn/system-proxy.json（0600，目录0700）在首次系统修改前原子落盘。macOS flock 内核锁保护启用/恢复，保留稳定锁文件；并发操作立即失败，不依赖 PID 文件回收。执行系统命令时由独立进程组的监护进程继承锁描述符，持有至命令结束，确保主进程崩溃后孤儿 setter 不会越过恢复锁；监护进程的10秒超时在主进程死亡后仍有效。恢复每项前持久化进度，地址已恢复但开关恢复失败也能重试。已有活跃快照禁止第二个进程覆盖。单条 networksetup 命令超时10秒；无 shell 拼接；只在生命周期执行，不增加数据转发路径的检查、计时器或额外网络跳转。

系统命令使用 macOS 自带 /usr/sbin/networksetup；实际 -help 已校验命令形态。代理种类与 PAC 的设置含义参见 [Apple 官方说明](https://support.apple.com/en-gb/guide/mac-help/mchlp2591/mac)。

## 拆分与实施

1. system/proxy.ts：命令适配、解析、持久化与回滚、所有权检查及互斥。
2. start.ts：实际端口、启动顺序、信号退出、失败回收；App.start 任何监听失败均释放先前资源。
3. API + CLI：关闭系统代理、停止服务、控制端点清理、幂等恢复；README、package stop 脚本。
