# 订阅刷新与转发性能

状态：已核销。级别：中；使用 feature-dev-v2 的方案、测试、独立审查流程。

## 契约与裁决

用户要求高性能，订阅同步不能拖慢 VPN 访问。

- 数据转发不读取配置文件、不发订阅请求、不增加全局锁或额外队列。
- 重载复用配置未变化的 AnyTLS 客户端/会话池和自动测速组；选择节点或只改规则不重新握手、不全量测速。
- 配置变更后的新连接走新出站；旧出站已有及已经开始建立的连接自然结束。退休客户端不接受新的 connect，不保留空闲池；没有活跃会话后立即释放。停止 App 时全部关闭。
- 复用未变的规则提供者及 GeoIP 视图，避免刷新清空已加载规则或重复解析数据库。
- 帧接收、单块流读取、单块 socket 写入避免多余整块拷贝；半包拼接、字节序及 padding 语义保持。
- HTTP/SOCKS 每次 idle timeout 在读完成或失败后撤销，不积累挂起计时器。

## 并发与预算

沿用单个 API 重载；新路由准备成功前不修改旧路由。失败只释放本次创建的资源。退休集合仅持有尚有活跃会话的旧客户端，零后台退休轮询；退出时全部回收。普通请求/数据包不做配置比较。

## 边界

不更改 TLS 认证、证书校验、协议 padding、已有缓冲上限和系统网络设置。公网实际速度仍受节点和线路约束，结果只报告本地实测。

## 实施与测试计划

1. 保存当前实现基线；加入可重复的回环性能脚本，测稳定传输、建连和刷新。
2. 重载资源按身份保留/释放；旧连接排空；自动测速停止和所有权分离。
3. 热路径减少拷贝，清理 idle timeout；回归半包、非零 byteOffset、多个帧、写错误和 EOF。
4. 本地 AnyTLS 测试断言选择/规则更新保留客户端身份、连接池和活动流；换节点配置后新流走 B、旧流继续 A、停止回收退休资源；失败不得关闭复用资源。
5. 四门、覆盖率、同脚本基线/优化多轮测量与独立对抗审查，记录结果，不以不稳定的墙钟阈值阻断 CI。

## 实测与核销

同机 Bun 1.4.3、macOS 回环；3 组交替运行的独立进程，每组每条路径 5 轮、每轮 32 MiB 用户载荷，64 KiB 块。保留当前优化前快照作为基线，两版使用完全相同脚本、TLS/padding 和回显服务。

| 指标（各进程中位数的中位数） | 优化前 | 优化后 |
| --- | ---: | ---: |
| AnyTLS 回显吞吐（单向载荷 MiB/s） | 771.287 | 846.088 |
| 完整 HTTP CONNECT → AnyTLS 回显吞吐（单向载荷 MiB/s） | 568.562 | 620.254 |
| 重载 + 建连 + 128B 回显 P50（ms） | 0.629 | 0.039 |
| 重载 + 建连 + 128B 回显 P95（ms） | 0.732 | 0.066 |
| 保留未变客户端的刷新次数 | 0 / 240 | 240 / 240 |

完整代理链路回环吞吐提升约 9.1%，刷新/建连/回显中位耗时降低约 93.8%。这是本地回环测量，不能代表公网节点带宽。原始每轮数据在 [vpn-performance-results.json](vpn-performance-results.json)。复现：`bun run tools/bench-vpn.ts`。
