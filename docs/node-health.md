# 每个节点的延迟与可用状态

状态：已核销。级别：中。按 feature-dev-v2 方案、测试与独立审查流程实施。

## 契约与裁决

用户裁决：只展示每个节点的延迟（ms）和可用状态，不做下载速率测试。

- `nodes --list`：完整节点表，读取当前内核最近探测结果，不发起探测、不选择节点。
- `nodes --check`：手动轻量探测订阅中每个可用 AnyTLS 节点，然后展示完整表；`--node NAME` 可限定一个节点，此组合只探测、不选择。
- 普通 `nodes` 的选择列表展示相同状态；`status` 展示全部节点最近探测，替代每地区首个代表。无样本明确显示“未探测”，实际失败显示“不可用/超时”，0ms 是有效延迟；超过5分钟的结果标注“上次结果”。
- 探测仅请求现有固定 HTTP 目标的 HEAD，延迟包含建连至首次回应时间，不是下载带宽。不开启后台新计时器，不自动下载、不切换当前节点、不改系统代理或运行模式。
- POST `/proxies/:name/healthcheck`：沿用 Host/secret 检查。200 返回最近 health；404 节点不存在；400 不支持探测；409 正在关闭、重载或节点在探测中被替换；429 探测并发已满。关闭/重载后不发布旧节点结果。
- 仅缓存于现有出站的健康历史（最多10样本），相同出站热重载复用；替换节点自然清空，进程重启后显示未探测。旧内核缺少端点时明确提示重启，离线不误判节点不可用。

## 问题域与预算

展示与手动轻量探测；不实现带宽测试、主动切换、测速排名或新增周期探测。现有订阅自动策略组探测由原策略组负责。

API 同时最多4项手动探测，同一节点不重复探测；CLI 最多4个请求并发。单节点端到端3秒（包含建连），CLI请求超时5秒；HEAD请求和回应读取均有固定上界。手动探测使用独立临时 AnyTLS client，结束/超时后关闭临时 client 与已创建流，取消未完成拨号并回收迟到连接，不关闭承载日常流量的 client，不留下未清理计时器。既有自动策略探测保留会话复用。展示和聚合只在命令/API请求时执行，不改变转发热路径。

## 拆分与实施

1. 健康摘要增加最近探测时间；修复探测超时未覆盖建连、计时器未清理的问题，保留10样本上界。
2. API 手动探测入口及并发保护；CLI 公用健康读取/格式化与有限并发刷新。
3. nodes 的 --list/--check 和交互提示；status 使用实际控制端点与鉴权，展示每个节点；README。

## 测试口径

- 未探测/失败/成功/0ms/过期结果，完整节点遍历而非地区去重，旧接口缺时间字段的显示。
- API Host/secret、不存在/不支持、并发上界、重复节点、重载/关闭中、探测途中替换节点。
- 探测成功、异常、永不返回、迟到建连均释放流和计时器。
- CLI 子进程：nodes --check → --list → status，使用本地 AnyTLS 测试服务器；验证所有节点（同地区两个）、端口0/secret寻址、原选中节点/模式/配置不变；失败与离线均不误报。
- 四门、覆盖率、独立审查；无真实订阅访问或宿主代理修改，无新增 skip。
