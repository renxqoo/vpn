# 订阅与运行配置同步

状态：已核销。级别：中（修复跨 CLI、持久配置、运行内核的一致性）。

## 契约

- `config set-subscription URL` 更新家目录以及已配置订阅的 cwd/.env，清除跨订阅的旧选择；下载最新订阅并请求运行内核重载。未运行则供下次启动使用；失败明确提示，不声称已生效。
- `nodes` 获取最新订阅、清理失效选择；选择完成后要求内核重载配置再切换。
- 新增 `POST /configs/reload`，沿用 Host/secret 校验，无请求参数，由启动进程读取自己的配置文件并下载订阅，204 成功，400 加载失败，409 并发刷新，501 不支持重载。错误沿用 `{message}`，不输出订阅 URL/凭证。
- 重载替换出站、策略组、规则及规则提供者；监听端口、API secret 和运行模式保持；启动进程以 0600 的 controller.json 记录实际端口/secret，CLI 优先使用活跃进程端点（显式 --api-port 可覆盖）。性能优化后复用未变节点的会话池，旧配置的活动连接自然排空；停止内核时全部回收（详见 vpn-performance.md）。新配置不可用时保留运行配置。
- 缓存以订阅 URL 的 SHA-256 命名；不使用无法确认来源的历史 sub.yaml。下载与缓存内容解析通过后才能使用。

## 问题域

处理显式订阅更新、节点命令与启动时的配置同步。不增加后台定时订阅更新；用户直接修改文件后通过 nodes 或重启生效。规则提供者沿用现有后台刷新语义。

## 并发/一致性预算

同一内核最多一个重载；下载超时 30 秒，CLI 重载请求 90 秒；缓存/订阅读取沿用 64 MiB 限制。重载期间最多两套路由资源，持久化失效选择清理成功、路由准备成功后无 await 地交换引用并释放不再使用的资源，旧活动连接自然排空；停止后不能发布在途配置。

## 拆分与实施顺序

1. URL 隔离缓存、解析校验及选择有效性判定。
2. App 准备路由与发布路由分离，API 暴露受保护的重载入口。
3. CLI 写入有效来源并同步内核；启动/重载清理无效选择；文档与回归。

## 裁决

按现有 `.env > 家目录` 优先级更新实际生效来源；沿用固定节点选择组。保持有效选择，失效时回退订阅组默认项并删除旧 selected-node。无需额外后台轮询。

## 测试口径

- A 订阅缓存不能用于 B；同 URL 离线可兜底；无效下载不能覆盖好缓存。
- 旧选择移除、有效选择保留、未知协议不可被标为有效选择。
- 设置订阅更新 .env 有效来源并保留无关键；新 URL 清除旧选择，同 URL 保留。
- API 未授权/无回调/失败/并发分支；失败后旧配置可用。
- 本地 AnyTLS A/B 装置验证重载后新流量到 B、旧节点消失、规则同步、监听端口不变。
- 隔离 HOME/cwd 的 CLI 子进程验证设置、nodes、配置和运行内核的一致终态。
